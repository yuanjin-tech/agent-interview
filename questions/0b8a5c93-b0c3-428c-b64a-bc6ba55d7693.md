# 问题

如何判断应该使用单 Agent 还是多 Agent 架构？

# 回答

默认应从单 Agent 开始，因为它的状态、调试、评测和责任归属更简单。先通过改善工具名称与描述、缩小参数 Schema、动态装载工具和拆分确定性步骤来解决问题。

只有出现明确证据才拆分多 Agent：不同子任务需要相互冲突的指令或上下文；工具集合相似导致稳定选错；需要并行的独立专业任务；或必须以权限、数据域和故障域进行隔离。

拆分后要算全链路代价：路由错误、上下文丢失、代理间协议、共享状态冲突、额外的 token/延迟，以及谁对最终结果负责。多 Agent 不是单 Agent 的“高级版”，而是用分工收益交换分布式协调成本。

# 面试考察点

是否能先给出拆分证据，再说明协调、状态和评测代价。
