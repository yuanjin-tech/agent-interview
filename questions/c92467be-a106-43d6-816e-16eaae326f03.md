# 问题

高并发 Agent 系统应如何处理限流和背压？

# 回答

先区分模型 API、每个工具、数据库、浏览器/沙箱和租户自身的并发与速率上限。入口层做按用户/租户的配额、请求大小限制和公平排队，避免一个长任务耗尽全局资源。

编排层不能无界并行子任务。为每类下游设置并发信号量、有界队列、超时和电路熔断；对 429/503 遵循 `Retry-After` 或指数退避加抖动。队列满时应拒绝、降级或返回可查询的异步任务 ID，不能继续在内存中堆积。

重试也要占用预算，防止重试风暴；对可合并查询批处理，对重复请求去重，对非关键步骤降级模型或延后执行。监控队列深度、排队时间、各依赖的限流率、并发数、放弃率和总任务时限。

# 面试考察点

是否能从无界并行、排队、公平性和重试风暴设计稳定性。
