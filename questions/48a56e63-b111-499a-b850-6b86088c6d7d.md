# 问题

Agent 上下文窗口不够时应如何处理？

# 回答

先用 token 明细确认消耗来源：系统指令、工具 Schema、历史消息、工具输出、检索文档和预留输出空间。处理的原则是“计算预算，再按任务相关性分配”，而不是在 API 报错后盲目截断尾部。

常用策略包括：只保留最近对话并将较早内容压缩为带来源的摘要；把文档、大型工具结果和中间产物存在外部，只传当前需要的片段和引用；动态选择工具 Schema；对重复内容去重；对长任务保存结构化计划、决策和待办项，而非依赖完整聊天记录。

压缩后要回归测试约束、用户意图、未完成任务和引用是否丢失。“窗口能放下”不等于“模型能有效使用”，仍需控制噪声。

# 面试考察点

是否会做可观测的 token 预算，并保护任务状态而非机械删文字。
