# 问题

Agent 工具过多且经常选错时应如何优化？

# 回答

先通过轨迹和混淆矩阵确认是哪些工具互相混淆，不要只看工具总数。常见原因是名称含糊、描述重叠、参数过宽、一个工具承担多个意图，或缺少“不适用条件”。

优化顺序可以是：

1. 重写工具名称、边界和 Schema，合并同义工具或拆分多意图工具。
2. 根据当前任务、用户权限和状态只暴露少量候选工具，用确定性路由或轻量模型先做工具集检索。
3. 给高频混淆对增加正反例，对高风险工具加确认或前置规则。
4. 在固定数据集上评测工具选择、参数正确率和不应调用时的拒绝率。

只有当不同工具组需要显著不同的上下文或权限边界时，才考虑拆成多 Agent。

# 面试考察点

是否用可观测数据定位混淆，并优先修复工具设计与候选集。
