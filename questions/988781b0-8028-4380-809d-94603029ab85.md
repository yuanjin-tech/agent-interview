# 问题

Agentic RAG 与固定 RAG 流程有什么区别？

# 回答

固定 RAG 通常由程序预先确定路径：查询改写→检索→重排→生成。Agentic RAG 让模型在运行中决定是否检索、选哪个数据源、如何拆分或重写查询、证据是否足够，以及是否追加检索。

Agentic RAG 更适合多数据源、多跳问题和信息需求不明确的场景，但它增加了延迟、成本、路由失败、无限检索和安全风险。如果单次检索已能稳定解决问题，固定流程更容易优化和测试。

评测应把路由决策、查询改写、文档召回、证据归因、最终答案和检索次数/成本分开。否则只看最终答案，无法定位是检索问题还是生成问题。

# 面试考察点

是否能说明动态决策带来的收益与额外失败面。
