# 问题

Agent 重试后重复发送邮件或重复扣款，应如何修复？

# 回答

根因通常是把“没收到成功响应”误判为“没有执行”。超时发生时，下游可能已完成副作用，因此直接重试不安全。

修复方案是将一次用户意图映射为稳定的幂等键，例如 `run_id + action_id`，而不是每次 HTTP 尝试重新生成。工具服务端以该键原子地记录处理状态和结果；重复请求返回原结果，不再执行。对下游支持幂等键的付款/消息 API，传递同一键。

如果返回结果未知，先查询或对账，不要让模型自行猜测并再发一次。同时修正重试分类，设置唯一消费、事务性 outbox 或状态机，并对重复幂等键和不确定结果告警。

# 面试考察点

是否能识别分布式系统的“响应丢失”，而不是只改 prompt 或减少重试次数。
