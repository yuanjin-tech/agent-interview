# 问题

远程 MCP Server 的身份认证和授权应如何设计？

# 回答

先分清三个主体：资源所有者、MCP Client 和受保护的 MCP Server。对 HTTP 传输，可按 MCP 授权规范使用基于 OAuth 2.1 的流程；Server 是资源服务器，Client 代表用户获取访问令牌。本地 stdio Server 不套用这一 HTTP 授权流程，通常从受控环境获取凭据。

安全要点包括：使用 HTTPS 和 PKCE；短期令牌与安全的刷新机制；按需申请最小 scope；Client 在授权请求中标明目标 resource，Server 校验 token 的签名、过期时间、issuer、audience/resource 和 scope。不得把上游 token 原样透传给下游服务。

授权不能停在“可以连接 Server”。每次 Tool/Resource 请求都要根据用户身份、租户、资源所有权和操作类型执行对象级授权，并记录可审计的代理关系。

# 面试考察点

是否能区分登录、令牌受众校验、scope 与对象级业务授权。
