# 问题

如何设计一个容易被 Agent 正确调用的工具？

# 回答

工具应做一件边界清晰的事，名称用动词表达目的，描述写明“什么时候用、什么时候不要用、会产生什么副作用”。参数使用类型明确、尽量小的 Schema，通过 enum、范围、格式和必填字段消除歧义，不要让模型生成 SQL、shell 或任意 URL 来代替业务参数。

返回值应结构化、简短且可区分成功、可重试错误、业务拒绝和权限拒绝。错误信息要给出下一步可行动信息，但不泄露内部堆栈和密钥。

最后，工具服务端必须自行做认证授权、参数校验、幂等和审计，不能因为“调用是模型选的”就信任其输入。用真实的正例、近似工具反例和边界参数建立回归集。

# 面试考察点

是否同时考虑模型的可选性以及后端的安全与可靠性。
