# 问题

Agent 效果不好时，应如何判断用提示词、RAG 还是微调解决？

# 回答

先用失败样本定位问题，而不是从技术名词选方案。

- 如果目标、约束、工具边界或输出格式不清晰，先改提示词、Schema 和工作流。确定性规则应放在代码中，不要靠微调“记住”。
- 如果缺少的是外部、私有、经常变化或需引用的事实，用 RAG 或工具在运行时获取，同时单独评测召回与归因。
- 如果输入输出映射稳定、有大量代表性高质量样本，而基础模型经过清晰提示后仍稳定地出现特定行为错误，才考虑微调，如特定格式、领域语言风格或工具选择行为。

三者可组合，但微调不是知识库和授权系统。每个方案都应在同一回归集上比较质量、成本、延迟和维护性。

# 面试考察点

是否能区分指令问题、动态知识问题和稳定行为学习问题。
